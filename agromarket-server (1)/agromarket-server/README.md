# АгроМаркет API

Express 5 + PostgreSQL. Товары и заявки хранятся в базе, полный CRUD, централизованная обработка ошибок, Postman-коллекция с автотестами.

## Запуск
```
npm install
npm run dev        # http://localhost:3000
```
Больше ничего не нужно: если в `.env` не задан `DATABASE_URL`, сервер использует встроенный PostgreSQL (PGlite): данные лежат в папке `pgdata/` и не пропадают после перезапуска, таблицы и товары создаются сами при первом запуске. SQL, схема и запросы те же, что и на обычном сервере.

Чтобы работать с настоящим сервером PostgreSQL: создать базу `agromarket`, скопировать `.env.example` в `.env`, указать пароль в `DATABASE_URL`, затем `npm run db:init` и `npm run dev`.
Сбросить данные: остановить сервер, удалить папку `pgdata/` и запустить снова (или `npm run db:init`).

## Ответы на вопросы для защиты

1. **Первичный и внешний ключ.** Первичный ключ — уникальный номер строки (`id SERIAL PRIMARY KEY` в обеих таблицах). Внешний ключ — `orders.product_id REFERENCES products(id)`: заявка должна ссылаться на существующий товар. `ON DELETE SET NULL`: при удалении товара у его заявок `product_id` становится `NULL`, сами заявки не пропадают.
2. **Ограничения orders.**
   - `NOT NULL` (name, email, quantity, status) — база не сохранит строку без этих полей.
   - `CHECK (quantity >= 10)` — отклонит заявку на меньший объём.
   - `CHECK (status IN (...))` — отклонит неизвестный статус.
   - `REFERENCES products(id)` — отклонит несуществующий product_id.
   - `PRIMARY KEY` — id уникален.
   Каждое нарушение даёт ошибку PostgreSQL, API отвечает 400.
3. **SQL-инъекция** — когда пользователь управляет текстом SQL-запроса через вклеенное значение. Защита: параметризованные запросы, например в `routes/products.js`: `pool.query('SELECT * FROM products WHERE name ILIKE $1', [...])`. Текст запроса и значения передаются в базу раздельно, значение всегда остаётся данными.
4. **`.env`** хранит секреты (пароль от базы) и настройки конкретной машины. В Git он не должен попасть, потому что репозитории сканируют боты. `.env.example` без настоящего пароля попадает в Git и подсказывает, какие переменные нужны.
5. **CRUD.** Create — INSERT — POST — 201. Read — SELECT — GET — 200. Update — UPDATE — PUT/PATCH — 200. Delete — DELETE — DELETE — 204.
6. **PUT и PATCH.** PUT заменяет ресурс целиком (не переданные поля станут NULL), PATCH меняет только переданные поля. DELETE возвращает 204 («успешно, возвращать нечего»): ресурса больше нет, тела у ответа нет.
7. **LEFT JOIN** показывает заявку, даже если товара нет (`product_name = null`). Обычный JOIN такие заявки потерял бы: например, после удаления товара или с пустым product_id.
8. **Обработчик ошибок.** Express отличает его по четырём параметрам `(err, req, res, next)`. Текст ошибки 500 клиенту не отправляют, чтобы не раскрывать устройство сервера (имена таблиц, пути к файлам); подробности пишутся в терминал.
9. **CHECK и проверка в JS.** JS-проверка даёт понятный ответ и экономит запрос к базе, а CHECK гарантирует корректность данных, даже если они пришли мимо API.
10. **Пул соединений** переиспользует открытые соединения, а не открывает новое на каждый запрос (это дорого). `import 'dotenv/config'` должен быть первым, потому что `db/pool.js` читает `DATABASE_URL` в момент импорта; если .env ещё не прочитан, подключение упадёт.
